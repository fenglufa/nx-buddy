# NX 小助手  
## 产品需求文档 PRD V1.2  

**文档状态：** 完整稿（待你确认后出 Word）  
**日期：** 2026-09-22  
**产品名称：** NX 小助手（对外不以 MCP 称呼产品）  
**目标客户（本项目）：** 长沙华恒机器人 / 华恒智能仓储与物流机器人相关设计团队（立库结构 + AGV/RGV/堆垛机/货叉等机械本体）  
**主语言：** C# / .NET  
**目标环境：** Windows（不强制 Win11）+ **Siemens NX 2412**  

---

## 1. 背景与问题

企业使用西门子 NX 做三维设计与工程图，并开始用 Cursor / Claude / Codex 等 Agent 提效。当前缺口：

- Agent 不能直接理解 PRT；西门子无官方 NX MCP。社区方案能力宽、安全模型不一，不宜直接当商品交付。
- 非标孔、非标板厚、错误图框、缺失焊缝/明细等，往往事后才被发现。单项目图纸可达数百到上千张。
- 华恒这类客户的图以 **板焊结构 + 物流机器人机构** 为主，通用「画个块」不够，还必须能卡公司孔系、型钢/板厚、外购件与出图规范。
- 正式文件可能在 PLM，但 **V1 只审本地检出目录**。

NX 小助手要做的是：在客户已安装的 NX 2412 上，给人和 Agent 同一套可执行的公司标准，以及可审计的操作入口。不是再做一个 CAD，也不是做 AGV 调度或立体库软件。

---

## 2. 产品目标与非目标

### 2.1 目标

- 设计师用自然语言让 Agent 在本机 NX 中按参数创建/修改模型（受规则约束）。
- 指定本地目录后，用 NX 打开 PRT/工程图，按规则库比对并出具可审计报告。
- **同一规则包**同时用于画图拦截（防）和事后审图（查）。
- 交付可安装商品：托盘管理端 + 无窗口 MCP + NX 插件；离线授权；不交付源码。
- 覆盖华恒两类对象：**库体/输送等结构件** 与 **物流机器人机械本体**（车架、货叉、轮边、护罩）。

### 2.2 非目标（V1）

- 不替代 NX 建模界面，不做独立 CAD。
- 不以视觉模型看 PDF/截图作为主审图手段。
- 不替代持证工程师签字放行。
- 不对接 Teamcenter / 其它 PLM，不写回「已审/已发放」。
- 不管客户使用哪一种 Agent 客户端，只保证本机托盘与 MCP 进程。
- 不做 AGV/RGV 导航调度、WMS/WCS、货位算法、激光视野、SLAM。
- 不做焊接机器人离线编程、焊枪可达、DH 参数。
- 不做 CAM、刀路、机床仿真、后处理、任意 `run_python`。
- 不做完整钣金模块、复杂曲面、齿轮专用件。
- 不承诺 NX 12 / 1980 / 2206 / 2312；V1 锁定 **2412**。
- 不承诺「安装包不可反编译」。

## 5. 产品原则

- MCP 是插头，产品名是 NX 小助手。
- 几何与图纸对象必须经 **NX 进程**读取；文件夹只提供清单。
- 规则外置；代码只做抽取与比对。
- 硬规则程序判；大模型只解说 findings。
- 画图为防、审图为查，标准版本号必须一致。
- Agent 不需要源码；工具 Schema 即说明书。
- 物流机器人进范围 = 机械本体与结构件合规，≠ 车辆软件。

## 6. 整体架构

一个安装包，三个组件：

| 组件 | 形态 | 职责 |
|------|------|------|
| `NxAssistant.exe` | 托盘 + 设置窗 | 授权、规则包、路径、日志、连接状态 |
| `NxAssistant.Mcp.exe` | 无窗口，`--mcp`，被 Agent 拉起 | 官方 C# SDK `ModelContextProtocol`，stdio |
| `NxAssistant.NxPlugin.dll` | NX 2412 启动加载 | NXOpen；本机 IPC |

关系：

```
Agent ──stdio──► MCP 宿主 ──本机 IPC──► NX 插件 ──NXOpen──► NX 2412
                      │
                      ├─ 规则引擎（company_v3）
                      └─ 报告（xlsx + JSON）
```

要点：

- NXOpen 只存在于 NX 进程。C# 不能取消插件或批处理会话。
- 审目录：宿主可拉起批处理 NX，不要求用户已打开窗口。
- 交互画图：依赖已启动并加载插件的 NX。
- UI 进程与 MCP 进程分离，禁止同一进程既弹窗又占 stdio。
- IPC 仅 `127.0.0.1` 或命名管道，带令牌。

## 7. 功能需求

### 7.1 安装与桌面

- Windows 安装程序；可选部署 `%UGII_USER_DIR%\startup`。
- 若用户已有 UGII 定制根：**禁止覆盖**，改为合并说明。
- 托盘常驻；状态区分：未授权 / 已授权 / NX 未连接 / MCP 忙碌。
- 设置分页：连接、授权、规则、工作区与报告路径、日志。
- 提供可复制的 mcp 配置片段（command 为安装目录绝对路径）。
- 不提供「在小助手窗口里建模」。

### 7.2 画图与改图（创作面）

V1 工具白名单见第 9 节。行为要求：

- 变更类工具在 commit 前走规则；失败返回 `rule_id` + 建议值，不得先建再报。
- 使用稳定对象 id，禁止让 Agent 死记面/边序号。
- `save` / `export` 限于配置的工作区根（FILE-001）。
- `undo_last_assistant_change` 只撤小助手上次变更。
- 单位不明则先问；默认按工作件单位。

### 7.3 审图（质量面）

用户：「审核项目 A 目录。」  
Agent 调用 `review_folder({ path })`，**不**在对话里循环打开每一张。

内部顺序：

1. 枚举工作区下 `*.prt`（及约定工程图对象）  
2. 启动或复用 NX 2412  
3. 打开 → 抽取结构化 JSON → 对规则包  
4. 单张失败记 finding，继续  
5. 写 `审图报告.xlsx` + 摘要 JSON  
6. Agent 解说统计；细查再 `inspect_*`

支持 `run_id`、进度查询。默认串行。规模按数百到上千张设计调度，SLA 按现场机器测定后写入合同，不在本 PRD 写死分钟数。

### 7.4 规则包

**包名：** `company_v3`  
**子包：** `huaheng_logistics_robot_v1`  

力度：`block` / `warn` / `off`，可按阶段配。报告与工具错误均带 `standard` 字段。

#### 7.4.1 通用 20 条（开发测试包已定义）

孔：HOLE-DIA-001、HOLE-BOLT-002、HOLE-THD-003、HOLE-DUP-004  
草图/特征：SKETCH-001、SKETCH-002、FEAT-EXT-001、FEAT-FILLET-002  
实体：BODY-001、BODY-002  
工程图：FRAME-001、TITLE-001～004、VIEW-001、DIM-001  
图层：LAYER-001、LAYER-002  
文件：FILE-001  

孔系列示例：光孔 6 / 6.6 / 7 / 8 / 8.5 / 9 / 10 / 11 / 13 / 14 / 17 / 18 / 21 / 22。  
**φ13.2 必须失败**，建议 13 或 14。图号示例 `P-21007-03`，版本 `A.2`。  
图框占位：`FRAME_A0_V3`～`A4_V3`（上线前替换为华恒真实图框 id）。

#### 7.4.2 华恒物流 / 机器人子包（V1 新增）

| 规则方向 | 默认 | V1 程度 |
|----------|------|---------|
| 板厚白名单 | 失败 | 精确匹配客户表；表未到前用可配置占位 |
| 型钢/方管规格 | 失败或警告 | 对标题栏或属性「规格」 |
| 出图须有焊缝符号 | 失败或警告 | 只查「有没有」，不评焊脚工艺 |
| 明细/外购件词典 | 失败或警告 | 轴承、舵轮、减速机、滚轮、气缸等 |
| 法兰/孔组 | 失败 | 对 2～3 个常用驱动法兰样本（客户提供） |
| 销轴/轮轴孔径 | 失败 | 并入孔系列 |
| 传感器安装孔 | 警告 | 仅孔径白名单，不查视野 |
| 外轮廓倒钝 | 警告 | 移动设备护罩 |

客户未提供正式表前：规则可运行，标准值可替换，**禁止把猜测规格写死进代码**。

### 7.5 读图—比对—结果（验收金样）

抽取：`feat_hole_15.diameter = 13.2`，无例外。  
规则：HOLE-DIA-001。  
结果：失败；邻近 13、14。  
报告行含：图号、版本、规则、对象 id、视图、实际值、建议。

## 8. 授权与 Key

### 8.1 模式

- 完全离线。  
- 一 Key 一机；N 席位 = N 张 Key。  
- 时长：按年或自定义 `not_before` / `not_after`。  
- 先发未绑机 Key，**首次成功激活写入机器指纹并锁定**。  
- 换机：产品方作废旧证、重签。  
- 只有产品方签发工具能生成可通过验签的 Key。

### 8.2 载荷字段

`lic_id`，`customer`，`seats`（固定为 1），`not_before`，`not_after`，`features`，`machine_hash`（激活后），`standard_pack`，`issued_at`，`issuer`。  
Key = 载荷 + 私钥签名。

### 8.3 签发与校验

- 签发工具 **单独分发**，私钥口令保护，永不进入客户安装包。  
- 签发台账：编号、客户、期限、是否作废。  
- 客户端：验签 → 验期 → 验指纹（已锁定时）→ 通过则缓存。  
- 未授权 / 过期：托盘明示；`status`/`license_status` 可读；create / review 返回 `LICENSE_INVALID`。  
- 不承诺不可伪造；防普通扩散 + 合同。

## 10. 使用流程（对用户可见）

**画图：** 用户说需求 → Agent 调白名单工具 → 规则拦截非标 → NX 出现模型。用户不必指定源码。  

**审图：** 用户给本地目录 → Agent 一次 `review_folder` → 小助手用 NX 扫目录 → 出 xlsx → Agent 读摘要说明。打开 NX、对规则都在工具内部。
